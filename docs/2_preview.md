# preview — 형상 탐색

> **스캔이 아니라 측량이다.** 물체의 형상을 모르는 상태에서 시작하여(실물에는 GT 가
> 없다) 높이·반경·적정 작업거리를 측정한다. 이 결과가 후속 단계의 입력 전부다.
>
> 선행 `1_calibration.md` · 후속 `3_lookaround.md`
>
> **검증 상태** — sim 에서 동작·수렴을 확인하였다(합성 콜백 회귀 포함). **실물 미검증**(P4).

## 0. 결정 요약

| 대상 | 판정식 / 목적 | 임계 | 코드 |
|---|---|---|---|
| **거리 격자·탐색 한계·시작 거리** | 작동거리 창에서 유도한다. 축거리 `d` 에서 창에 드는 반경은 `r ∈ [d−far, d−near]` → 한 스텝이 포괄하는 반경 폭 = 창 폭 | `r_max` 180mm | `standoff.preview_grid` / `probe_bounds` |
| **다음 축거리** (점이 있을 때) | 표면거리 **중앙값** `p` 를 창 중앙 `c` 로: `d ← d + (c − p)` | 창 중앙에서 창폭/4(최소 10mm) 이내면 유지 | `standoff.distance_correction` |
| **다음 축거리** (점이 0일 때) | 방향을 알 수 없으므로 가까이·멀리 교대로 탐침한다 | 40mm 씩, 최대 6회 | `standoff.blind_probe` |
| **캡처 유효성** | 두 단계 **모두** 충족해야 한다(①은 스캐너 문제, ②는 조준 문제) | ① raw ≥ 1500 ② 크롭 후 ≥ 200 | `RAW_MIN_VERTS` / `MIN_USEFUL_PTS` |
| **조준높이 상승 여부** | ① 해당 프레임의 밀도 상단이 시야 안이면 종료 ② 아니면 상단 증가량 확인 | ① 상단−조준 < 0.5·d·tan(vfov/2) ② 증가 < 10mm 면 종료, 최대 4회 | `TOP_SEEN_FOV_FRAC` / `top_eps_m` |
| **계획 산출 가능 여부** | 누적 점 수 | ≥ 100 | `MIN_PLAN_PTS` |

**최적화가 아니다.** 목적함수 없이 **되먹임 한 줄**로 동작한다 — 한 장 촬영하고 측정하여
다음 거리를 계산한다. 탐색이 아니라 측정이므로 통상 1~2회에 수렴한다.

## 2. 측정 대상

| 축 | 결정 방식 |
|---|---|
| 조준높이 `tz` | 원판 상면 +5cm 에서 시작하여 상승한다. 해당 프레임에서 **물체 끝이 시야 안에 보이면 종료**, 아니면 "상단 + 3cm" 로 상승(최대 4회). 물체 높이를 모르는 상태로 종료할 수 있다 |
| 축거리 `d` | **들어온 점군의 거리 분포로 조정한다**(§3) |
| 방위 `θ` | 턴테이블 **0/90/180/270° 네 방향**. 각 점군은 `−θ` 로 되돌려 물체 프레임으로 통일한다 |
| 유효 판정 | `min_pts`(기본 200) 미만이면 미취득으로 처리한다 |

⚠ 방위가 두 방향(0/90°)이면 넓은 물체의 하부가 절반만 취득되어 플래너가 미관측 영역을
"면이 없다"로 오독한다(실측: 하단 밴드 전부 기각, 커버 58%→94%).

근접한계 안쪽에서도 잡음 몇 점은 반환되는데, 이를 유효 취득으로 처리하면 중앙값이
왜곡되어 거리가 **잘못된 방향으로** 수렴한다.

> `d` 는 **턴테이블 축까지의 거리**이고 작동거리 창은 **표면까지의 거리**로 정의되므로
> 혼용하지 않는다. 반경 97mm 물체에서 축거리 225mm 는 표면 128mm 이며, Spider 근접한계
> (170mm) 안쪽이라 데이터가 나오지 않는다. 변환은 `standoff.axis_standoff(r)` 한 곳에서만
> 수행한다.

## 3. 거리 결정

### 모든 거리는 작동거리 창에서 유도된다

하드코딩된 거리가 없다. 격자·탐색한계·시작거리가 모두 스캐너가 제공하는 near/far 에서
계산된다.

카메라는 **축**을 거리 `d` 에서 조준하지만 스캔되는 것은 **표면**이다.

```
   카메라 ●──────────── d ────────────┆ 축
              ├── d−r ──┤
                        ○ 표면 (축에서 반경 r)
```

표면까지가 `d − r` 이므로 창에 드는 반경은 `r ∈ [d − far, d − near]` 다.
**한 거리가 포괄하는 것은 반경 한 구간이고 그 폭이 곧 창 폭이다.** 따라서 반경
0~`r_max` 를 덮으려면 창 폭 간격으로 스텝을 배치한다(`d_k = far + k·(far−near)`).

창 200~300mm(폭 100mm) · `r_max` 180mm 인 경우, `d=300` 이 r 0~100mm 를, `d=400` 이
r 100~200mm 를 포괄하여 두 스텝으로 이어진다. **어느 스텝에서 취득되는지 자체가 반경
측정이다.** 탐색 한계도 동일하게 하한 `near`, 상한 `far + r_max` 로 유도된다.

| 창 | 폭 | 격자 | 탐색한계 |
|---|---|---|---|
| 200~300 (현재 가정) | 100mm | (300, 400) | 200~480 |
| **170~350** (Spider 스펙) | 180mm | **(350)** — 한 스텝 | 170~530 |
| 210~265 (좁게 튜닝) | 55mm | (265, 320, 375, 430) | 210~445 |

> ⚠ 이 값이 sim·real 양쪽에 하드코딩되어 갈라져 있던 시기가 있었다. 창을 변경하면
> (`set_scanning_range`·기종 교체) 양쪽이 조용히 틀어진다. 현재는 스캐너 조회값에서
> 유도한다.

### 점이 취득될 때

표면까지 거리 중앙값 `p` 가 나오면 그 방위의 국소 반경이 `r ≈ d − p` 다. 표면을 창
중앙 `c` 에 배치하려면 `d_next = c + r = d + (c − p)` 다. 중앙값을 사용하는 이유는
히스토그램 꼬리(바닥·배경 잔재)에 영향받지 않기 때문이다. 창 중앙에서 불감대(창 폭의
1/4) 이내면 이동하지 않는다.

격자 전체를 높이마다 순회하던 방식은 작은 물체에서 먼 스텝이 빈 캡처가 되는데도 이동은
수행하여 시간을 낭비했다. 현재 격자는 **적응이 실패했을 때의 폴백**으로만 유지한다.

수렴한 거리는 `d_cur` 로 다음 높이·방위에 이월된다. 따라서 첫 높이에서만 몇 차례
이동하고 이후는 대개 1회다(실측 10회 → 8회, 전부 유효).

### 높이 상승 종료 조건

조준높이 상승 여부는 **해당 프레임만 보고** 판단한다. 밀도 상단(`robust_top_height`)이
조준높이 위로 시야 반높이(`0.5·d·tan(vfov/2)`, d=300mm 에서 38mm) 이내면 **물체 끝을
이미 관측한 것**이므로 상승하지 않는다. 확정된 상단은 방위 간에 공유한다.

상단을 누적 점군의 max 로 판정하면 반사·배경 잡음 몇 점에 끌려 허공을 조준하게 된다
(실측: 실제 55mm 물체에서 167mm 조준, 4방위에서 반복되어 8 이동 중 4회 낭비). 밀도
상단은 같은 프레임에서 70~75mm 로 정확하다.

판정을 누적이 아니라 프레임 단위로 하는 이유는, 누적에서는 하단 점이 압도적이라 2%
문턱을 상부가 넘지 못해 키 큰 물체가 조기 종료되기 때문이다(합성시험 250mm 물체가
125mm 에서 정지). 프레임 기준이면 225mm 까지 상승하여 상단 250mm 를 시야 안에서
확인하고 종료한다.

### 점이 전혀 없을 때

**반환 0 은 방향을 알 수 없다는 의미다.** 가까이·멀리를 교대로 확장하며 탐색한다.

```
k=1: d−40mm   k=2: d+40mm   k=3: d−80mm   k=4: d+80mm   …   (최대 6회)
탐색 한계 = [near, far + r_max] = 200~480mm
```

가까운 쪽을 **먼저** 확인하는 순서는 유지한다 — 멀어서 비는 경우가 더 흔하고 가까운
쪽이 밀도·정밀도에도 유리하다. 다만 한쪽만 탐색하면 실패한다. 반경 110mm 물체는 시작
축거리 300mm 가 표면 190mm 로 근접한계 안쪽이므로, 더 가까이 가면 탐색이 실패 방향으로
진행된다.

검증(합성 콜백, 창 200~300mm, 시작 300mm):

| 경우 | 이동 |
|---|---|
| 보통 r=40mm | **1회** (표면 260mm ≈ 창중앙 — 유지) |
| 작은 r=5mm | **2회** (300→255) |
| 큰 r=110mm (시작이 근접한계 안쪽) | **3회** (300 → 260 반환0 → 340 확정) |

## 4. 콜백 계약 — `(점군, 카메라위치)` 2-튜플

콜백이 카메라 위치를 함께 반환해야 적응이 활성화된다(표면거리를 측정하지 못하면 보정식이
성립하지 않는다). 판정은 **형태**로만 한다.

| 콜백 반환 | 해석 |
|---|---|
| `(pts, cam)` | 정상 |
| `(pts, None)` | **이번 프레임만** 카메라 미취득 → 보정만 생략하고 **적응 유지** |
| `pts` (맨 배열) | 구 계약 → 고정 격자로 영구 전환 |

> ⚠ 이 둘을 `cam is None` 하나로 겸하던 시기에는 빈 캡처 한 번에 실행 내내 적응이
> 영구 비활성화되었고, 그 판정이 탐침보다 앞에 있어 빈 캡처가 `blind_probe` 에 도달조차
> 하지 못했다. 적응이 가장 필요한 순간에 비활성화되는 구조였으며, real 은 반환이 전부
> 맨 배열이라 적응이 한 번도 동작하지 않았다.
>
> 이런 결함은 **조용히** 진행된다(스캔은 완료되고 결과도 나오는데 거리만 맞지 않는다).
> 따라서 정적 검사를 상설화하였다 — 하드웨어·Isaac 없이 0.3초다.

## 5. 설정 항목

| env | 기본 | 내용 |
|---|---|---|
| `MMS_WORK_STANDOFF_MM` | 225 | 카메라↔**표면** 목표 거리. **물리값**이므로 실측 작동거리 창 중앙에 두고 변경하지 않는다 |
| `MMS_STANDOFF_BIAS_MM` | 0 | **오차 주입.** 의도적으로 틀린 거리에서 출발시켜 추종 동작을 확인한다 |

| `MMS_SIM_PREVIEW_EL` | 30 | preview 고도각 (sim) |
| `MMS_SIM_WD` / `MMS_SIM_WD_FILTER` | — | sim 스캐너의 작동거리 창과 필터 |

작동거리 창(near/far)은 **스캐너에 조회한다** — real 은 SDK `scanning_range()`, sim 은
그 계약을 모사한다. 계획기의 가정과 스캐너 설정이 갈라지지 않도록 하기 위함이다.
값 변경은 `ArtecConfig` 의 `scan_range_near_mm` / `scan_range_far_mm` 로 한다.

> ⚠ `WORK_STANDOFF_MM` 과 `BAND_OVERLAP`(`3_lookaround.md`)은 **동일 증상에 대한 두 해법**
> 이다. 둘을 동시에 조정하면 이중 보정이 되므로 겹침 쪽만 사용한다.

# 〔부록〕 문제 해결

### P1. preview 가 점을 전혀 수집하지 못한다

먼저 **종료 사유**를 확인한다. 두 메시지의 의미가 반대다.

```
… 반환 없음, 탐색범위(200~480mm) 소진        ← 가능한 거리를 모두 탐색했으나 없다
… 시도 6회 소진 (다음 후보 460mm — 안 감)     ← 탐색할 거리가 남았으나 예산이 소진
```

**`시도 N회 소진`** 이면 거리 문제일 수 있다. 굵은 물체라 시작 거리에서 멀거나
`max_dist_tries`(기본 6)가 부족한 것이므로 상향하여 재실행한다.

**`탐색범위 … 소진`** 이면 거리 문제가 아니다. 다음을 확인한다.

- **카메라가 다른 곳을 조준하고 있다** — `output/<RUN>/debug/cam/preview/` 스냅샷을
  먼저 확인한다. `crop=0` 의 원인을 IK·충돌·프레임 변환·관절 리밋 순으로 배제하다가
  실제 원인이 카메라 조준이었던 사례가 있다(USD articulation 영점과 해석 FK 영점이
  29° 어긋남 — `isaac_xarm.JOINT_ZERO_OFFSET`). 이미지 한 장으로 판별된다.
- **크롭이 물체를 전부 제거한다** — `crop_object_points` 의 축·디스크 상면·`up_sign` 을
  확인한다. real 은 base 의 +Z 가 아래이므로 `up_sign=-1` 이어야 한다.
- **`pts=N — N점뿐 (<200)`** 이 반복되면 스캐너가 관측하는 것이 물체가 아니다
  (자기점 잔여·배경). 문턱은 `min_pts` 다.

### P2. 물체 높이를 실제보다 작게 판정한다
상단 종료 조건(`top_eps_m`, 기본 1cm)과 최대 상승 횟수(4회)를 확인한다. 얇은 돌출부는
"상단이 증가하지 않았다"로 오판될 수 있다. 밴드 센터 inset 이 일부 보정하나 근본 대책은
아니다. 실측 사례: 플래너 `h=215mm` 인데 결과 메시는 252mm 였다.

### P3. 탐색이 한쪽 한계에서 중단된다
`blind_probe` 가 범위 밖 탐침에 `None` 을 반환하고 호출부가 이를 "전부 소진"으로
해석하여, 좁은 쪽이 먼저 소진되면 넓은 쪽에 남은 거리를 사용하지 못했다.

```
이전:  260 · 340 · 220 · 380 · (180 = 한계 밖) → 중단   실효 220~380mm
현재:  260 · 340 · 220 · 380 · 420 · 460              ← 180 을 건너뛰고 계속
```

현재는 범위 밖 탐침을 건너뛰고 다음 유효 탐침을 계수한다. `None` 은 **양쪽 모두**
소진된 경우에만 반환되므로 로그의 "탐색범위 소진" 이 사실과 일치한다.

> 남은 제약은 예산이다. `max_dist_tries=6` 이므로 한 조준높이에서 캡처는 6회(시작 1 +
> 탐침 5)까지이며, 위 수열에서는 420mm 까지 도달한다. 탐침 하나가 로봇 이동 1회이므로
> 무한정 늘릴 수 없다. 굵은 물체에서 부족하면 `max_dist_tries` 를 상향한다.

### P4. 〔미검증〕 real 에서 양쪽 탐색·잡음 문턱을 확인하지 않았다
§3 의 양방향 탐색과 `min_pts` 문턱은 **sim 합성 콜백으로만** 검증하였다. 실물에서
확인할 항목은 다음과 같다.

- 근접한계 안쪽이 0점이 아니라 잡음 몇 점으로 반환될 때 `min_pts`(200)가 실제로
  걸러내는가. 문턱을 넘는 잡음이 발생하면 중앙값이 왜곡된다. 로그의
  `N점뿐 (<200) — 노이즈로 보고 버림` 이 정상 동작이다.
- 굵은 물체(r≳100mm)에서 탐침 수열이 먼 쪽으로 확장되는가. sim 런은 r=34mm 라 첫
  스텝에서 취득되어 이 경로를 사용하지 않았다.

### P5. 빈 시야 잡음과 실제 패치의 구분 — 응집도 게이트
Spider 는 아무것도 없는 시야에서도 300~500점의 산발적 잡음을 반환하며, 이 점들은 원시
문턱(150)도 크롭도 통과한다. 실측에서 허공의 423·283점이 물체로 인정되어 거리추종이
축거리를 300→404mm 로 밀어낸 사례가 있다. 원시 문턱을 1500 으로 올리면 잡음은
걸러지지만 뚜껑(350점)도 함께 배제되어 높이를 36mm 낮게 판정한다.

따라서 **공간 응집도**로 구분한다. 4mm 이웃이 8개 이상인 점이 150개·30% 미만이면 빈
시야로 판정한다(`preview_min_coherent_pts` / `_frac`). 실측에서 실제 패치는
230~9,600점/46~94%, 잡음은 5~62점/2~15% 였다.
