# 충돌 검사와 IK

> 로봇을 어떤 자세로 보낼 수 있는가(IK)와 이동 경로에서 무엇을 치지 않는가(충돌)를 다룬다.
> lookaround 는 밴드마다 자세를 새로 풀어 이동하고 nbv 는 매 반복 자세를 새로 푼다.
> 어느 쪽이든 경로 검사가 부실하면 문제가 드러난다 — 밴드 간 이동은 대상물 바로 옆을
> 통과한다.
>
> **도달 불가·충돌 판정이 나오면 하드웨어 한계보다 평가 코드를 먼저 의심한다.**
> 해당 사례가 부록에 넷 있다.

---

## 1. 사용법과 설정

검사는 **모든 이동이 경유하는 단일 지점**에 위치한다. sim 은 `_drive()`, real 은
`_move_robot_to_q()` 가 `CollisionModel` 을 호출하므로 lookaround·nbv·flip 이 자동으로
적용된다. 호출부에서 별도 처리는 필요하지 않다.

```python
from utils.collision import collision_model as cmod
cm = cmod.get_default(self_margin_m=0.020, env_margin_m=0.025)
ok, why      = cm.is_pose_safe(q)          # 자세 검사
ok, why, s   = cm.is_path_safe(q0, q1)     # 경로 검사 (보수적 전진)
```

⚠ 캐시가 없으면 `get_default` 가 `None` 을 반환하고 **검사가 통째로 비활성화된다.**
`[collision] 모델 로드 실패` 가 출력되면 그 상태로 로봇을 구동하지 않는다.

### 캐시 (필수)

| 파일 | 내용 | 생성 |
|---|---|---|
| `utils/collision/data/xarm7_spider_links.npz` | 링크·툴 표면 점군 (링크 로컬) | `scripts/sim/export_link_meshes.py` |
| `utils/collision/data/cell_env.npz` | 셀 구조물 점군 (**로봇 base 프레임**) | `scripts/sim/export_env_mesh.py` |

base 프레임으로 생성하므로 sim·real 공용이다. **실물 셀을 개조하면 반드시 재생성한다** —
미수행 시 존재하지 않는 구조물을 회피하거나 존재하는 구조물을 통과한다.

> ⚠ 재생성에는 **Isaac Sim 이 필요하다**(USD 씬을 열어 생성한다). 현장 PC(`mms-env`)에서는
> 수행할 수 없다. 실물이 CAD 와 달라졌을 때의 현장 대응은 **§6** 을 참조한다.

### 설정 값

| 설정 | 내용 | 기본 |
|---|---|---|
| `self_margin_m` / `env_margin_m` | 자가·환경 충돌 여유 | 0.020 / 0.025 |
| `min_sigma` | 특이점 임계 σ_min (§4) | 0.05 |
| `sdf_voxel_m` / `link_voxel_m` | 환경·링크 SDF 격자 | 0.008 / 0.006 |
| `sdf_pad_m` / `link_pad_m` | 격자 여백 | 0.15 / 0.12 |
| `max_query_pts` | 링크당 질의점 상한 | 2500 |

sim 은 여유 두 값을 환경변수로도 받는다(`MMS_SIM_SELF_CLEAR`, `MMS_SIM_ENV_CLEAR`).
`min_sigma = 0` 을 지정하면 특이점 판정만 해제하고 충돌만 검사한다.

## 2. 검사 방식

```
로봇  = 링크 로컬 메시 점군을 해석 FK 로 배치
환경  = SDF 거리장 8mm   ← O(1) 조회
자가  = 링크 로컬 SDF 6mm ← 속도의 근거
        clearance → is_pose_safe → is_path_safe
```

**자가충돌도 SDF 로 전환한 것이 핵심이다.** 프로파일링 결과 자세당 114.5ms 중 111ms 가
자가충돌 KD-tree 질의였고 환경 SDF 는 36k점에 6.6ms 였다. 동일 방식을 자가에 적용하여
**자세당 5.75ms**(20배 개선)가 되었다.

격자 밖 조회는 `pad` 를 반환한다. 격자가 bbox+pad 를 포함하므로 밖의 점은 최소 pad 만큼
떨어져 있다는 **참인 하한**이며, 따라서 거짓 '안전' 판정이 발생하지 않는다.

검사 대상 쌍은 툴↔link1~5 와 link6↔link1~3 이다. link6/7 은 툴이 부착된 인접 링크라
항상 접해 있고, link1/2 는 천장 마운트에 상시 근접하므로 환경 검사에서 제외한다.

### 경로 — 보수적 전진

> 자세 q 의 여유가 s 이고 구간에서 어떤 점도 s 보다 멀리 이동하지 않으면, 그 구간은
> **중간 검사 없이 안전이 보증된다.**

|  | 검사 횟수 | 소요 |
|---|---|---|
| 동일 자세 | 2회 | 11.6ms |
| 관절1 5° | 2회 | 10.6ms |
| home→0 대이동 | 35회 | 243.8ms (고정 123스텝은 707ms) |

빠르면서 **터널링이 원리적으로 불가능**하다. 고정·적응 샘플링은 모두 샘플 사이를
검사하지 못한다.

### 우회

직선 경로가 차단되면 `utils/control/joint_path_planner.py` 의 RRT-Connect 가 우회
경로를 탐색하고 shortcut 으로 평활화한다. 실측에서 안전 자세 12개 중 직선이 차단된
쌍이 6개였고, 시험한 3개 모두 우회에 성공했다(1.3~2.3s). 우회가 없으면 자세의 절반
가까이를 사용하지 못한다. 검사한 경로를 그대로 주행하므로 **검사와 실행이 일치한다.**

## 3. IK

솔버는 `utils/robot/xarm7_kinematics.ik`(자체 해석 DLS) 하나다. **xArm SDK IK 는 사용하지
않는다** — 컨트롤러 통신이라 하드웨어 연결이 필요하고 왕복 지연이 있는데, 계획 단계에서는
후보 수백 개를 오프라인으로 풀어야 하기 때문이다.

자세 생성도 `utils/robot/view_pose.solve_view_q` 로 통일되어 있다. 이전에는 sim 만 roll
6방향·시드 8개를 사용하고 real 은 각각 1개여서, **동일 솔버를 쓰면서도 sim 에서 가능한
자세가 real 에서 도달 불가로 배제되었다.**

카메라 규약(sim=USD, real=OpenCV)은 통일하지 않고 **인자로 전달한다.** 두 규약은 카메라
로컬 Y축 180° 회전 하나만 다르고(`diag(-1,1,-1)`) 원점은 완전히 일치하므로, 규약을
데이터로 전달하면 **캘리브레이션을 변경할 필요가 없다.**

roll 을 푸는 것의 중요성은 T2 를 참조한다.

## 4. 특이점 — 관절각 규칙이 아니라 σ_min

`xarm7_kinematics.sigma_min(q)` 로 자코비안 최소 특이값을 확인하고 `min_sigma = 0.05`
미만이면 자세를 거부한다. 충돌은 아니지만 **명령해서는 안 되는 자세**이므로 동일
게이트에서 차단한다. 여기에 두면 자세 선정·경로 보간·우회 계획에 전부 자동 적용된다.

**단위 정규화가 필수다.** `_numeric_jacobian` 은 위치 행이 mm/rad 이므로 그대로 SVD 하면
위치가 1000배 커서 회전 특이점이 묻힌다. 위치를 m 로 변환하고 회전에 특성길이 0.3m 를
곱한다.

무작위 1500자세 분포는 최소 0.0004 / 1% 0.0020 / 5% 0.0076 / 중앙 0.069 다. 0.05 는
하위 약 4% 를 배제하고 home(0.147)에 3배 여유를 남긴다.

**7축에서는 6축의 손목 특이점(q5=0)이 특이점이 아니다** — 실측 σ_min 0.16 으로 나머지
축이 보상한다. 실제로 문제가 되는 것은 팔꿈치가 상한까지 펴진 q4≈157° 형상이며, 이는
**자코비안을 확인해야만** 드러난다. 관절각 규칙은 이 팔에서 잘못된 결과를 낸다.

## 5. 원칙 — 턴테이블이 방위각을 담당한다

로봇이 방위각을 생성하기 위해 물체 주위를 선회하면 팔이 크게 감싸는 자세가 되어
위험해진다. 물체중심 조준, standoff 0.313m 실측 결과다.

| az | 관절이동 | 자가여유 | 환경여유 | 판정 |
|---|---|---|---|---|
| **0°** | **58°** | **52mm** | 217mm | OK |
| 30° | 95° | 60mm | 137mm | OK |
| −30° | 362° | 12mm | 0mm | 충돌 |
| −60° | 409° | **3mm** | 18mm | 충돌 |
| −90° | 445° | **1mm** | 112mm | 충돌 |
| 180° | 345° | 68mm | 0mm | 충돌 |

16개 조합 중 9개가 충돌로 기각되며, az 를 벌릴수록 관절이동이 8배 증가하고 여유가 1mm
까지 감소한다. 반면 **방위 커버리지는 턴테이블 전회전이 이미 제공한다.**

따라서 `VIEW_AZIS_DEG` 를 `[0, 30, -30]` 으로 축소하였다(`MMS_SIM_VIEW_AZIS`).
**턴테이블 = 방위각, 로봇 = 고도각·거리**가 이 셀의 기본 원칙이다.

## 6. 실물 셀이 CAD 와 다른 경우

여기서 오류가 발생하면 오탐이 아니라 **미탐**(충돌 가능한데 안전으로 판정)이므로 결과가
파손이다.

### 6.1 캐시의 성격

```
CAD(STEP) ──step2usd──▶ 씬 USD ──export_env_mesh.py──▶ cell_env.npz ──▶ 환경 SDF
```

CAD 기반이 맞으나, CAD 를 직접 읽는 것이 아니라 **CAD→USD 씬을 한 번 생성한 스냅샷**이고
생성 도구가 Isaac Sim 에 종속되어 있다는 점이 제약의 근원이다.

| 파일 | 내용 | 셀 변경 시 |
|---|---|---|
| `xarm7_spider_links.npz` | 로봇 자신 — 링크 로컬 점군 + 툴 | 영향 없음. 툴 교체 시에만 |
| `cell_env.npz` | 셀 구조물 — base 프레임 점군 | **매번 어긋난다** |

> **`names` 는 활용할 수 없다.** USD 메시 이름이 전부 `mesh` 라 부재 단위 식별이
> 불가능하다. "저울만 제외하고 재생성" 같은 조작은 이름으로는 불가능하며 좌표로
> 절단해야 한다(§6.4).

### ★ base 프레임은 Z 가 아래로 증가한다

팔이 천장에 매달려 있어 base 가 뒤집혀 있다. `world → base` 는 **Y축 180° 회전**
(X→−X, Z→−Z) + 원점 `(0.365, 0, 1.500)` 이다. 패치 좌표를 수기로 작성할 때 가장 빈번한
오류 지점이다.

| 부재 | world Z | base z |
|---|---|---|
| 천장 마운트 하면 | 1.500 | **−0.055** |
| 턴테이블 상면 | 0.665 | **0.835** |
| 상판 `universal_plate` 상면 | 0.510 | **0.990** |
| 바닥(캐스터 하단) | −0.071 | **1.571** |

환산: `base_z = 1.500 − world_z`, `base_x = 0.365 − world_x`, `base_y = −world_y`.

### 6.2 현장에서 수정할 수 없는 이유

| # | 제약 |
|---|---|
| 1 | **재생성에 Isaac Sim 이 필요하다.** `export_env_mesh.py` 가 `SimulationApp` 을 기동하고 USD stage 를 연다. 현장 PC 에는 `mms-env` 만 있다 |
| 2 | **CAD 를 먼저 수정해야 한다.** 실측 → CAD → STEP → USD → npz 는 반나절 소요 루프다 |
| 3 | **margin 으로 대체할 수 없다.** margin 은 *존재하는* 장애물과의 거리에만 작용한다. 모델에 **없는** 구조물은 거리 계산에 포함되지 않으므로 `env_margin_m` 을 100mm 로 올려도 그대로 충돌한다 |

3번이 핵심이다. **CAD 와 실물의 차이는 "여유 부족"이 아니라 "데이터 부재"다.**

### 6.3 대응 순서

**0단계. 어긋난 정도를 먼저 측정한다.**

캐시 전체가 로봇 base 에 앵커되어 있으므로, 프레임이나 로봇 마운트가 이동했으면
**개별 부재가 아니라 점군 전체가 어긋난다.** 이를 확인하지 않고 부재를 하나씩
패치하면 수렴하지 않는다.

```powershell
$ISAAC = "$env:USERPROFILE\miniforge3\envs\env_isaacsim\python.exe"
& $ISAAC scripts\sim\view_scene.py v3        # 현재 기준 씬을 눈으로 확인
python scripts/artec/calibrate.py --only 3   # T_B_F0 재측정
```

`T_B_F0` 의 원점을 위 표의 `(0, 0, 0.835)` 와 대조한다. 어긋나면 **거기서 중단하고**
원인(프레임 이동 / 로봇 재장착 / 턴테이블 이설)을 먼저 규명한다.

앵커가 일치하면 개별 부재로 진행한다. 부재 위치는 로봇 TCP 를 특징점 옆으로 조그하여
읽는 것이 가장 정확하다.

> ⚠ `status.py` 의 TCP 는 **플랜지 기준**(TCP offset 0)이지 툴 끝이 아니다.
> 툴 체인 265mm 를 감안하여 읽는다(`hw_layout.md` §1).

**1단계. 실측 프리미티브 패치 — 현장에서 가능한 유일한 방법.**

변경된 구조물을 박스·원기둥·평면으로 근사하여 yaml 에 기술하고, 로드 시 점군으로
샘플링하여 `env` 에 합친다. 환경 SDF 는 점군만 받으며 점의 출처를 구분하지 않으므로,
박스를 5mm 간격으로 샘플링하면 CAD 에서 생성한 점과 동등한 장애물이 된다.

**근사는 반드시 실물보다 크게(외접) 설정한다.** 과대추정은 오탐(자세 몇 개 손실),
과소추정은 미탐(파손)이므로 위험이 비대칭이다.

⚠ 아래는 **미구현**이며 작성이 필요하다.

| 작성 대상 | 내용 |
|---|---|
| `config/cell_env_patch.yaml` | 프리미티브 목록. **base 프레임 m, Z 아래로 증가** |
| `utils/collision/env_patch.py` | yaml → 점군. `spacing_m=0.005` (SDF 복셀 8mm 보다 촘촘해야 한다) |
| 배선 2곳 | `CollisionModel.__init__` 과 `EnvCollision.__init__` 에서 각각 `np.vstack`. **두 곳 모두** — 동일 npz 를 독립적으로 읽는다 |
| `scripts/collision/plot_env_slice.py` | base 프레임 z 단면 확인. 패치가 잘못된 위치에 생성되는 사고를 막는 가장 저렴한 수단 |

```yaml
# config/cell_env_patch.yaml
# ⚠ world 가 아니라 로봇 base 프레임 (m). Z 는 아래로 증가 — §6.1
add:
  - {name: cable_tray, type: box,      lo: [0.20, -0.38, 0.95], hi: [0.55, -0.30, 1.02]}
  - {name: new_post,   type: cylinder, center_xy: [0.62, 0.21], z0: 0.10, z1: 1.55, radius: 0.045}
remove: []
```

**2단계. CAD/USD 동기화 (사무실).** 패치가 축적되면 이를 작업지시서로 삼아 CAD 를
수정하고 씬을 재생성한다. 절차는 `sim_scene.md` §3 에 있다. yaml 을 "CAD 에 미반영된
차이 목록"으로 운용하면 잔여 항목이 파일 하나로 파악된다.

### 6.4 제거는 추가보다 어렵다

추가는 `vstack` 한 줄이지만 제거는 점군에서 영역을 절단하는 작업이다. bbox 로 절단하면
그 안의 다른 부재까지 소실되고, `names` 가 단일 값이라 부재 단위 제외가 원리적으로
불가능하다(§6.1).

따라서 안전한 순서는 **"일단 유지하고, 자세가 실제로 부족할 때만 절단한다"** 이다.
존재하지 않는 구조물을 남겨두면 손해는 오탐에 그치며, `is_pose_safe` 의 거부 사유에
`env(link4,12mm)` 처럼 어느 링크가 무엇에 걸렸는지 표시된다.

### 6.5 패치 검증

1. **단면 플롯으로 육안 확인** — 좌표 부호 하나만 틀려도 구조물이 반대편에 생성된다.
   Z 뒤집힘(§6.1)이 가장 빈번하다.
2. **clearance 대조** — 로봇을 몇 자세에 세우고 `cm.clearance(q)` 의 거리를 실측값과
   비교한다. 오차가 margin 이내이면 사용 가능하다.

   ```python
   cm = cmod.get_default(min_sigma=0.0)   # 특이점 판정 해제, 거리만
   s, e, who = cm.clearance(q)            # (자가 m, 환경 m, 최근접 이름)
   ```

   > ⚠ `q` 는 **명령각**을 사용한다. 실측각을 사용하면 T5 의 `start` 거부 연쇄가 재현된다.
3. **A/B 비교**(T8) — 패치 on/off 를 전환하여 확인한다.

### 6.6 금지 사항

| 금지 | 사유 |
|---|---|
| margin 상향으로 대체 | 미탐에는 효과가 없다 (§6.2-3) |
| npz 를 삭제하거나 로드 실패 상태로 운전 | 검사가 통째로 비활성화된다(§1). 가장 위험한 선택이다 |
| 캡슐 world 만 수정하고 메시 env 를 방치 | 캡슐은 nbv 후보 사전 필터일 뿐이고 최종 게이트는 메시다(T4) |
| world 좌표로 yaml 작성 | base 프레임이며 Z 부호가 반대다 (§6.1) |

### 6.7 턴테이블 주변은 파라미터로 즉시 조정 가능하다

셀 구조물과 달리 턴테이블 주변은 CAD 에 종속되지 않는다. 실물 파이프라인의 캡슐 world 는
`T_B_F0`(캘리브 결과)와 설정값으로 매번 생성한다
(`artec_multipass_scan_session._build_collision_world`).

| 설정 | 내용 |
|---|---|
| `nbv_turntable_radius_mm` | disc(+프레임) 반경 |
| `nbv_turntable_body_height_mm` | 턴테이블 몸체 높이 |
| `nbv_keepout_radius_mm` / `_height_mm` / `_center_xy` | disc 위 금지 원기둥 |
| `nbv_collision_margin_mm` | 캡슐 여유 |

턴테이블을 교체·이설한 경우 **재캘리브레이션과 이 값 수정만으로 충분하며 npz 는 변경할
필요가 없다.** 다만 이는 사전 필터이므로 §6.3 의 메시 패치를 대체하지 않는다.

# 〔부록〕 문제 해결

### T1. IK 시드를 하나만 사용하면 도달 가능한 자세를 배제한다
수치해법(DLS)이므로 출발점에 따라 수렴이 달라진다. **실측: 수직 파지가 시드 1개면 0/8,
12개면 8/8.** 증상은 산발적 실패다.

### T2. 특정 고도각 대역이 전부 실패하면 roll 고정을 의심한다
스캐너는 광축 둘레로 회전해도 동일한 면을 관측한다. 그런데
`look_at(eye, target, up=(0,0,1))` 은 roll 을 하나로 고정한다. **실측: roll 고정 시
el 30° 자세가 0/8, 해제 시 5/8. 시드를 12개로 늘려도 roll 을 고정하면 여전히 0/8** 이므로
시드로 대체되지 않는다.

대역 전체가 실패하면 roll, 산발적으로 실패하면 시드(T1)다.

### T3. ⚠ 표면 샘플링 — 정점만 포함하면 부재 내부가 비어 있다
가장 위험했던 결함이다. 스캐너가 1m 길이 4040 프로파일 기둥을 **관통**했다. 부재 정점
1,694개가 전부 양 끝단에 집중되어 중간 1m 에는 0개였고, 점군 SDF 는 점이 있는 곳만
장애물로 인식하므로 중간이 빈 통로가 되었다.

CAD 압출·판재는 정점이 모서리에만 존재한다. `GetPointsAttr()` 만 사용해서는 안 되며
**삼각형 면적 비례 표면 샘플링**(`mesh_sampling.py`)을 사용해야 한다.

| | 전체 점 | 기둥 중간(0.3~0.7Z) |
|---|---|---|
| 이전 | 88,190 | **0점** ← 관통 |
| 현재 | 1,301,122 | 6,963점, Z 전 구간 균일 |

점이 15배 증가해도 판정 속도는 동일하다(SDF 격자 조회이므로 점 수와 무관).

> 검증 방법도 오류였다. 부재 자신의 정점으로 질의하여 끝단만 확인했다. 표면 전체를
> 훑어야 한다.

### T4. 캡슐은 꺾인 링크를 직선으로 덮어 오탐을 발생시킨다
링크 캡슐이 관절 원점을 잇는 직선이므로 꺾인 link4 를 덮으면 빈 공간까지 포함한다.
**실측: 캡슐 축간 58mm 로 충돌 판정이나 실제 메시 거리는 93mm.**

nbv 후보 필터의 캡슐 world 는 과대평가(안전 방향)이므로 유지하고 메시 검사를 추가하였다.
순서는 캡슐 scene → 메시 env → 메시 self 다.

### T5. `start` 거부 연쇄 — 명령각 vs 실측각
`is_path_safe(q0, q1)` 가 `start(...)` 를 반환하면 **출발 자세가 이미 여유 밖**이라는
의미다. 이때 목표까지 거부하면 이후 모든 이동이 동일 사유로 차단된다. hand-eye 하니스
실측에서 19 자세 중 7개가 이 연쇄로 소실되었다.

원인은 `q0` 의 출처다.

| | `q0` 출처 | 연쇄 위험 |
|---|---|---|
| 파이프라인 | `self._q` = **명령** 관절각 | 없음 — 게이트를 통과한 값을 재사용 |
| 하니스 | 아티큘레이션 **실측** 관절각 | **있음** |

드라이브 계통 오차(joint1 +1.4°)로 인해 게이트를 통과한 목표와 실제 도달 자세가 달라져
여유 밖으로 벗어난다. 하니스는 `start` 사유일 때 경고만 남기고 이동한다 — 출발 자세가
불량할 때 그 자리에 머무는 것이 더 위험하고, 목표는 이미 `is_pose_safe` 를 통과했기
때문이다.

홈 자세 여유 실측(기준 자가 20 / 환경 25mm): artec home 65.3 / 44.9mm,
`HOME_JOINTS_DEG["artec"]` 66.9 / 180.4mm. **홈에서 출발하는 한 파이프라인은 이 연쇄에
해당하지 않는다.**

### T6. 메모리
표면 샘플링에 상한이 없어 OOM 으로 작업 PC 가 정지한 사례가 있다. 세 단계로 방지한다.

1. `per_tri_cap` / `max_pts` / float32 — 극단 입력(10m² @1mm = 1억점)이 8,196점으로 제한
2. 삼각분할 완전 벡터화 — 파이썬 루프가 직접 원인이었다(23만 삼각형 0.03초)
3. `/tmp/runguard.sh <RSS_GB> <명령…>` — 초과 시 프로세스만 종료.
   `ulimit -v` 는 CUDA 가상주소 예약을 저해하므로 **Isaac 에 사용하지 않는다**

### T7. ⚠ IK 를 통일해도 두 솔버는 여전히 다른 자세를 산출한다

**계획 경로**는 해석 IK 로 통일되어 있으나 **캘리브 스크립트는 통일 대상이 아니었다.**
아직 SDK IK 를 호출하는 곳이 있다.

```
scripts/artec/hand_eye_calib.py      scripts/artec/intrinsic_calib.py
scripts/phoxi/hand_eye_calib.py      scripts/phoxi/make_poses.py
utils/control/hardware_layer.py      utils/control/theta_planner.py
```

더 중요한 것은 **FK 를 맞춰도 IK 는 일치하지 않는다**는 점이다. 7축은 동일 TCP 를
만드는 팔 형상이 무한히 많으므로(여유자유도), 두 솔버가 서로 다른 팔꿈치·손목 분기를
선택하면 손끝은 같아도 **팔은 전혀 다른 경로를 지난다.** 실측에서 FK 재교정
(1mm/0.18°) 이후에도 동일 TCP 자세의 Δq 최대가 140~251° 였다.

**사고 사례** — 캘리브 자세를 `ee_pose` 로 저장하자 `hand_eye_calib` 이 이를 컨트롤러
IK 로 재차 풀어서 이동했다. 해석 IK 로 통과시킨 충돌 검사가 무효화되었고, 첫 자세
이동에서 턴테이블과 충돌 직전까지 진행되었다(비상정지). 8개 중 3개가 위험했다.

**해법은 IK 통일이 아니라 IK 를 다시 풀지 않는 것이다.** 검증한 **관절각을 그대로
저장하고 그대로 실행**하면 시드·솔버에 의존하지 않는다(`gen_calib_poses.py` → yaml
`joints` 키 → `set_servo_angle`).

> 함께 확인된 사항 — `is_pose_safe` 만으로는 부족하다. 자세는 안전하나 경로가 차단된
> 경우가 있으므로, 자세마다 home 을 경유한다면 `is_path_safe(HOME, q)` 를 확인해야 한다.
>
> 또한 `kin.ik` 는 해를 관절 한계로 clip 한 뒤에도 `ok=True` 를 반환한다. 한계에 정확히
> 얹힌 자세가 통과하므로(실측 16개 중 4개가 여유 0.00°) 호출부에서 여유를 별도로
> 확인해야 한다 — 컨트롤러가 `set_servo_angle code 10` 으로 거부한다.
